# Architecture

Plica is a static, evidence-first knowledge base for real software systems. It is independent of Petwins application runtime and build dependencies.

## Single authoritative build

1. Editors maintain `cases.json`, `terms.json`, `papers.json`, and `relations.json`.
2. `validate_content.py` rejects invalid metadata, duplicate source records and dangling relations.
3. `build.py` uses only the Python standard library to generate `site/` HTML, public JSON indexes and the published Agent Skill.
4. `site/assets/` contains maintained CSS, JavaScript and SVG resources; these are source assets, not regenerated by `build.py`.
5. GitHub Actions tests the same scripts and publishes only `site/` through GitHub Pages.

Generated pages are retained in Git as inspectable release snapshots. They are not a separate editorial authority. Rebuild after source edits; never maintain two independent JSON catalogs or builders.

## Runtime

The browser uses HTML/CSS/JavaScript with relative internal URLs, allowing the GitHub Pages `/plica/` project prefix. Search is over the existing site's indexed editorial fields, not downloaded full text from external articles. Product, publishing organization and engineering mechanism are separate navigation/filter dimensions. Organization currently means the publishing company; independently modeled teams are not implemented.

Production cases, glossary, research papers, editorial comparison pages and the knowledge graph are statically generated. Graph text lists provide mobile access. Case–term edges are explicit reviewed data. Paper associations indicate topical relevance only, never proof of a production deployment.

The public Skill is maintained in `skills/plica-architecture/SKILL.md` and copied to `site/skill/plica-architecture/SKILL.md`. Its read-only index is `site/api/v1/index.json`, with terms at `site/api/v1/terms.json`.

## Boundaries

The selection sidebar prepares and copies a question; it does not run an AI model. There is no account system, inference API, payment/subscription service, real newsletter submission or sponsor transaction. Future paid AI requires a separate authenticated backend, privacy design, quotas and server-side billing. GitHub Pages must never contain provider credentials or pretend to enforce paid access.

## Quality gates

Content validation, deterministic generation, JavaScript syntax, internal-link checks and real HTTP browser tests run before deployment. Desktop/mobile and root/project-prefix navigation must both work. External-source factual accuracy and copyright review remain editorial work, not something the automated tests prove.

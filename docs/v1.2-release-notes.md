# Plica

**Inside the systems we use.** 一个从真实产品出发的系统元架构案例库。收藏第一手工程文章、论文与系统复盘：关注问题、约束、整体机制和设计权衡，而不是代码框架。

## Structure

- `cases.json` — 32 个有原始资料链接的独立编辑案例，可直接编辑。包括来源、发布日期、机制、设计取舍、原创导读。全部为独立撰写的简要概述，不复制原文图片或全文。
- `build.py` — 零依赖 Python 静态页面生成器，当前生成 130 个独立 HTML 页面（包含公司、术语、论文、知识图谱、Skill 与开放索引）。
- `terms.json` / `papers.json` / `relations.json` — 术语、论文与人工审定关系的编辑数据源。
- `site/` — 完整的无框架 HTML/CSS/JS 发布产物，可直接静态托管。
- `.github/workflows/deploy-pages.yml` — GitHub Pages 自动构建部署。

## Run locally

```bash
python3 build.py
python3 -m http.server 8000 --directory site
```

Then visit http://localhost:8000. You can also open `site/index.html` locally, though some browser restrictions may affect copying links.

## Publish on GitHub Pages

1. Create a new **public** repository (for example `plica`) and push **all project contents** — not only the `site/` directory — to `main`.
2. In **Settings → Pages**, choose **GitHub Actions** as the build and deployment source.
3. The workflow builds the site with Python and deploys `site/`. It uses relative URLs so the site works on project subpaths such as `https://<username>.github.io/plica/` and custom domains.
4. Confirm a successful workflow and test homepage, search, case detail and external article links in a real browser.

No backend and no secrets are required. Newsletter signups and sponsor inquiries are **not live**; site explicitly marks them as coming soon rather than pretending to submit forms.

## Editorial boundaries

- Always cite an original source and its date for technical claims; don't conflate a source's historical context with a company's current architecture.
- Google GFS is **not** claimed to be the present-day internals of Google Drive; ByteDance Monolith is **not** labeled as TikTok's verified current ranking system.
- Avoid full-text republication, unlicensed source images, fabricated performance numbers or fake sponsors.
- `cases.json` is the content source of truth; review the copy before editing and rebuilding.

## Scope

Current MVP: curated homepage, library with free-text search + company/area filters, products and systems indexes, 32 article pages with first-party citations, comparison narratives, about, sponsor placeholder, responsive mobile navigation, copy link and optional browser-local bookmark state.

Future: real CMS, newsletter service, site analytics, RSS, custom domain, editor-reviewed diagrams, richer side-by-side comparisons. No paid features yet.

## V1.1 — connected knowledge layer (2026-10-19)

- Separate **Product**, **Organization**, and **Mechanism** navigation and three simultaneous archive filters (plus search and shareable query parameters). The Company index is based on each case's publishing organization rather than conflating it with consumer-facing product names; separate named engineering teams are not yet individually represented unless the primary source identifies them.
- **Glossary** (`terms.json`, 18 curated entries), safe term links in Plica's own commentary, and context / related-case pages; 21 reviewed case–term relationships are stored in `relations.json` and are never generated automatically from prose during the production build.
- **Knowledge Graph** (`graph/`), a browsable mechanism / terminology / product / publishing-company map linking to production cases and topically related papers. Its source-of-truth term–case edges are editorially reviewed in `relations.json`; research connections signify topic proximity, **not** deployment evidence. Every graph topic has a readable text list for mobile and accessibility.
- Separate **Research** (`papers.json`, three verified arXiv entries), connected to case studies only as editorial thematic reading suggestions, never as unsupported claims that a company deployed the paper's method.
- **Selection sidebar** on Plica's own case editorial text: select a paragraph and click "向 Plica AI 提问" to see and copy a question with its local article URL. Automated AI responses, logins, paid membership and billing **are NOT implemented** and should not be described as live.
- Public **Agent Skill**: `skills/plica-architecture/SKILL.md` (also emitted to `site/skill/plica-architecture/SKILL.md`), with an open read-only static index at `site/api/v1/index.json` plus `terms.json`. Follow [Agent Skills specification](https://agentskills.io/specification).

The static generation command remains `python3 build.py` and requires only Python 3 standard library. Every edit to `cases.json`, `terms.json`, or `papers.json` requires review of source fidelity and re-running the generator.

For future paid AI: use a separate authenticated backend + metered inference + billing; GitHub Pages is only the public static frontend and cannot securely enforce paid access to a model. Do not publish any provider API keys in JavaScript or a public repository.

## Local QA / release

Run `python3 build.py`, `node --check site/assets/site.js`, and `python3 test_site.py` (Playwright + Chromium is required for offline visual smoke tests only, not for production). The test validates 130 independent pages and link integrity, desktop/mobile overflow, archive product/company/mechanism filters, glossary, graph, research, case selection sidebar. Screenshots of the homepage are emitted to `/mnt/data`. Local QA in this chat uses `page.set_content` with locally inlined scripts and stylesheet because normal browser navigation is restricted; production hosting should still be checked in a real browser after GitHub Pages deployment.

The site is not yet a paid service: there is no member login, inference API, subscription billing, or automated AI response.
